# 5. Enterprise Requirements

> Status: outline (carried over from the running notes)

What "good" means in practice across those use cases: correctness, task completion, action correctness, response usefulness, grounding/evidence quality, recoverability, safety, calibration, observability signals, user-perceived reliability, dataset coverage, and operational readiness for deployment.

## Categories

| Category | Requirements |
|---|---|
| Output quality | Correctness; relevance and usefulness; grounding and evidence quality; calibration |
| Task and action quality | Task completion; acceptance-criteria satisfaction; correct tool and action selection; correct target and resulting state |
| Workflow reliability | Context and handoff integrity; explicit ownership and closure; state continuity; concurrency and retry safety |
| Recovery and operations | Failure detection; recoverability; safe retry, resume, rollback, or compensation; outcome verification; observability requirements |
| User experience | Clear completion and uncertainty status; re-prompt, override, and abandonment behavior; trust after failure or recovery; appropriate human escalation |
